# Smart Construction Safety Monitoring System
## YOLO11 Object Detection | Muslih Uddin

A computer-vision project that uses a pretrained **YOLO11n (Nano)** object-detection model, fine-tuned on a construction-site safety dataset, to identify workers, personal protective equipment (PPE), machinery, and vehicles in construction-site images.

The project is developed in **Google Colab**. The dataset ZIP is downloaded manually from Kaggle and uploaded from the user's computer through the Colab file picker; **no Kaggle API key is required**.

> **Project status:** The notebook contains the training and evaluation workflow and a Gradio demo. The notebook's product interface is **Gradio, not Streamlit**. The shared Gradio link created by Colab is temporary. For a persistent public deployment, deploy the standalone app to a suitable hosting platform.

---

## 1. Project objectives

- Train a YOLO11n object detector for construction-site safety monitoring.
- Detect safety equipment and other relevant objects using bounding boxes.
- Identify detections labelled as PPE non-compliance categories, such as `NO-Hardhat`, `NO-Mask`, and `NO-Safety Vest`.
- Evaluate the trained detector using precision, recall, mAP@0.50, and mAP@0.50:0.95.
- Run inference on new images and display annotated results.
- Provide a simple interactive Gradio interface for image upload and detection.

## 5. How to run the Google Colab notebook

1. Open the `.ipynb` project notebook in Google Colab.
2. Select **Runtime → Change runtime type → T4 GPU** if GPU access is available.
3. Run the installation and import cell.
4. Run the dataset upload cell and select the Kaggle ZIP file from your computer.
5. Allow the notebook to extract the ZIP into `/content/construction_safety_data`.
6. Run the dataset validation and YAML configuration cells.
7. Run the training cell. The model trains for 25 epochs.
8. Review the training curves and metrics.
9. Run evaluation on the held-out test split (the notebook falls back to validation if a test folder is not present).
10. Run the prediction cell to see bounding boxes on a sample image.
11. Run the Gradio cell to launch the interactive demo.
12. Download `best.pt` and `results.csv` before the Colab runtime disconnects.

## 6. Evaluation metrics

The notebook evaluates the trained model on the test split when it is available; otherwise, it uses the validation split.

The reported object-detection metrics are:

- **Precision:** proportion of predicted detections that are correct.
- **Recall:** proportion of ground-truth objects that the detector successfully finds.
- **mAP@0.50:** mean Average Precision at an Intersection over Union (IoU) threshold of 0.50.
- **mAP@0.50:0.95:** mean Average Precision averaged across IoU thresholds from 0.50 to 0.95.

These are object-detection metrics. Ordinary image-classification accuracy is not a standard headline metric for YOLO object detection. Use the actual values printed by your notebook in the final report; do not insert estimated or assumed scores.

```python

results = detector.predict(
    source="construction_site.jpg",
    conf=0.25,
    imgsz=640,
    verbose=False
)

```

`best.pt` must be in the application's working directory, or the code must use its full file path.

## 8. Interactive Gradio application

The notebook includes a Gradio interface that:

- Accepts a construction-site image.
- Lets the user set the confidence threshold.
- Runs the trained YOLO detector.
- Displays the image with predicted bounding boxes and class labels.
- Shows counts for detected classes.
- Displays warning text when classes whose names begin with `NO-` are detected.

The notebook launches the interface with:

```python
demo.launch(share=True, debug=False)
```

The public `gradio.live` share URL is temporary and should not be treated as a permanent deployment URL.

### Run the generated `app.py` locally

The notebook includes a cell that writes a standalone Gradio `app.py` file. Put that file and the trained model in the same folder:

```text

├── app.py
└── best.pt
```

Then install dependencies and start the app:

```bash
pip install ultralytics gradio opencv-python-headless
python app.py
```

The application loads `best.pt` and performs inference; it does not train the model.

## 9. Limitations and responsible use

- Model performance depends on the quality, coverage, and annotation accuracy of the training dataset.
- Detection confidence is not the same as certainty. False positives and false negatives can occur.
- A detected `NO-Hardhat`, `NO-Mask`, or `NO-Safety Vest` label is a model prediction. It is not, by itself, proof that a particular worker has violated a safety rule.
- The model should be tested on varied real construction-site conditions, including different lighting, camera angles, distances, weather, and PPE types.
- This project is an educational prototype and decision-support tool. It is **not a certified safety inspection system** and must not replace qualified human safety officers or applicable workplace safety procedures.
